# 🧠 Engineering Philosophy

```text
                  SIMPLE
                     ▲
                     │
                     │
        RELIABLE ◄───┼───► SCALABLE
                     │
                     │
                     ▼
                MAINTAINABLE
```

I try to avoid complexity for complexity's sake.

My preferred engineering process is:

```text
Understand
   ↓
Simplify
   ↓
Design
   ↓
Build
   ↓
Test
   ↓
Ship
   ↓
Observe
   ↓
Improve
```

Some principles I care about:

```yaml
engineering:
  readability: > cleverness
  simplicity: > unnecessary abstraction
  measurement: > assumptions
  reliability: > flashy architecture
  shipping: > endless perfection
```

# 📐 Product Engineering

I like engineers who think beyond:

```text
"Does the code work?"
```

and start asking:

```text
Does anyone need this?

Can users understand it?

Can we maintain it?

Can we measure it?

Can it handle 10 users?

Can it handle 10,000?

What breaks first?

How expensive is it to run?

What happens when something fails?

Can another engineer understand this six months from now?
```

That intersection between **software engineering, systems thinking and product strategy** is where I enjoy working most.
